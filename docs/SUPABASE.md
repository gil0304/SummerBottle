# Supabase 同期セットアップ手順

Summer Bottle はローカルだけで完全に動作するアプリです。
このドキュメントの手順は**任意**で、複数端末間でボトルを同期したい場合にのみ必要です。
外部SDKは使用せず、アプリは URLSession で Supabase の REST API
(GoTrue / PostgREST / Storage)を直接呼び出します。

## 必要なもの

- Supabase アカウント(無料プランで可)
- メールを受信できるアドレス(ログインは6桁コードのメールOTP)

## 手順

### 1. Supabase プロジェクトを作成する

1. <https://supabase.com/dashboard> にログインし「New project」でプロジェクトを作成する。
2. リージョン・データベースパスワードは任意(アプリはDBパスワードを使わない)。

### 2. SQL エディタでスキーマを作成する

1. ダッシュボード左メニューの **SQL Editor** を開く。
2. このリポジトリの `supabase/migrations/001_init.sql` の内容を全文貼り付けて **Run**。
3. 以下が作成される:
   - テーブル `bottles` / `bottle_photos` / `bottle_objects` / `bottle_audio`
   - `updated_at` 自動更新トリガ
   - 全テーブルの RLS(自分の行 `user_id = auth.uid()` のみ読み書き可)
   - 非公開 Storage バケット `bottle-media` と、
     「パスの先頭フォルダ = 自分のユーザーID」のときだけ読み書きできるポリシー

同じSQLを再実行しても壊れません(冪等)。

### 3. メールOTP認証を有効にする

1. **Authentication → Sign In / Providers** で **Email** プロバイダを有効にする(既定で有効)。
2. アプリは「マジックリンク」ではなく**6桁コード**を使う。
   **Authentication → Email Templates → Magic Link** テンプレートの本文に
   `{{ .Token }}` が含まれるように編集する(例: `あなたの確認コード: {{ .Token }}`)。
   `{{ .Token }}` が無いとメールにコードが記載されず、ログインできない。
3. (任意)**Authentication → Sign In / Providers → Email** の
   「Confirm email」まわりの設定は既定のままでよい。OTPログインでは
   コード入力がそのまま確認を兼ねる。

### 4. URL と anon キーをアプリに設定する

1. ダッシュボードの **Project Settings → API** を開く。
2. **Project URL**(`https://xxxx.supabase.co`)と
   **anon public** キーをコピーする。
   ※ `service_role` キーは絶対にアプリへ入れないこと。
3. アプリの **設定タブ → 同期(Supabase)** セクションに
   URL と anon キーを貼り付けて「保存」。

### 5. ログインする

1. 同じセクションでメールアドレスを入力し「コード送信」。
2. 届いたメールの6桁コードを入力して「ログイン」。
   (初回はユーザーが自動作成される)

### 6. 同期する

- 「今すぐ同期」を押すと双方向同期が実行される。
- 別の端末でも同じ URL / anon キー / メールアドレスでログインすれば、
  同じボトルが同期される。

## 同期の仕組みと制約

| 項目 | 内容 |
|------|------|
| 方向 | 双方向。`updatedAt` を比較し**新しい方が勝つ**(コンフリクト解決はこれのみ。マージはしない) |
| タイミング | 手動(「今すぐ同期」ボタン)のみ。自動バックグラウンド同期はしない |
| データ本体 | `bottles.payload`(jsonb)に Bottle 全体をエンコードして保存する。仕様書17章のカラム(タイトル・日付・座標・`scene_config` 等)も冗長に埋めるが、**復元時は `payload` を正とする** |
| 子テーブル | `bottle_photos` / `bottle_objects` / `bottle_audio` は定義のみ(将来の拡張・SQLからの分析用)。現行アプリは書き込まない |
| 写真・音声 | Storage バケット `bottle-media` の `<user_id>/<bottle_id>/<fileName>` へ往復する。push 時はアップロード(既存は上書き)、pull 時はローカルに無いファイルだけダウンロードする。写真の枚数・サイズに応じて通信量と時間がかかる |
| 削除 | **削除は同期しない**(トゥームストーン無し)。片方で削除しても、もう片方に残っていれば次回同期で復活しうる |
| 認証 | メールOTP。アクセストークン/リフレッシュトークンは端末の Keychain に保存。401 時は自動でリフレッシュし、失敗したら再ログインを促す |
| セキュリティ | RLS により他ユーザーの行・ファイルには一切アクセスできない。anon キーは公開前提のキーであり、RLS が実質のアクセス制御になる |
| 秒精度 | 日付は ISO8601(秒精度)で保存するため、`updatedAt` の比較には約1.5秒の許容差を持たせている(同時刻更新は「同一」とみなす) |

## トラブルシューティング

- **コードのメールが届かない / リンクしか無い**: 手順3の `{{ .Token }}` を確認。
  無料プランの内蔵メールは送信数制限が厳しいので、本格運用時は SMTP 設定を推奨。
- **「サーバーエラー(401)」が続く**: 一度「ログアウト」して再ログインする。
- **「サーバーエラー(404)」**: URL の打ち間違い、または手順2のSQL未実行。
- **写真が表示されない**: 同期直後はメディアのダウンロードに時間がかかることがある。
  もう一度「今すぐ同期」を実行すると不足分だけ再取得される。
